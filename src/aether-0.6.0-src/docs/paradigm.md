# Aether 编程范式：面向百年的第一性原理（v0.2）

> 目标：一种对**智能体**和**人类**都"极度合适"的编程范式。
> 下面每条原则都标注了 **【已实现】**（v0.2 可运行）、**【部分实现】** 或 **【推测】**（目前只是判断，没有证据保证会这样发展）。

## 原则 0：程序是"意图"，不是"文本"
人写代码是为了表达"我要什么"。智能体擅长展开细节，人擅长判断"对不对"。
所以语言的核心单位应该是**可检查的意图声明**：数据是什么（entity）、允许做什么（action + 权限）、必须永远成立什么（契约）、长什么样（view）、按什么顺序发生（flow）、怎样算对（example/test）。
- 【已实现】一份 `.ae` 文件同时生成存储、API、界面、流程与测试。

## 原则 1：结构是真相，文本只是一种投影
一百年后，"源代码文件"大概率不再是唯一真相。真相是**结构化的程序图（IR）**；文本、可视化、自然语言都是它的"投影（projection）"，可以互相转换。
- 【已实现】三种投影：**文本**（.ae 源码）、**结构**（`aether ast` 的 JSON IR，Studio 中的 AST 树）、**自然语言**（`aether explain`，Studio「解释」页，基于规则、确定性，不依赖大模型）。
- 【推测】可视化投影（流程图、数据关系图）与语音投影；不同人看同一程序的不同投影。
- 诚实说明：v0.2 仍以文本为编辑入口，IR 由解析得到，而不是直接编辑 IR。

## 原则 2：内容寻址、版本化
程序的身份应该由**它的含义**决定，而不是文件名或格式。
- 【已实现】`aether hash`：对去掉行号/空白/注释的规范化 AST 做 SHA-256。只改格式或注释，哈希不变；改了语义，哈希改变。历史中每个版本都按此哈希存储。
- 【推测】函数级内容寻址（像 Unison 那样按定义哈希引用依赖），从而彻底消除"依赖地狱"与重命名冲突。v0.2 只做到整个程序级别。

## 原则 3：每一次修改都是可验证、可回滚、可追责的操作
- 【已实现】智能体只能提交**结构化操作**（add_field / rename / replace_decl / set_effects …），系统应用后**自动复检**并给出 diff。
- 【已实现】**操作日志与出处（provenance）**：每条记录包含作者（`human` / `agent:mock` / `agent:llm`）、时间、原因（提示词 + 摘要）、操作列表、前后语义哈希、是否语义变更。CLI：`aether ops --author --reason -w`、`aether history`、`aether undo`、`aether redo`；Studio「历史」页可撤销 / 重做 / 检出任意版本。
- 【部分实现】"可逆"目前靠内容寻址快照实现（每个版本都存下来），而不是对每个操作求逆。
- 【推测】每个补丁附带机器可验证的"证明"（类型、效果、契约、性能预算都没有变差）。

## 原则 4：规约与示例是语言的一部分
人类最擅长说"应该是什么样"，智能体最擅长"让它变成那样"。规约是两者之间的契约。
- 【已实现】`requires` / `ensures`（函数与动作，`result` 表示返回值），运行时检查，违反给出 R041 / R042 及表达式原文。
- 【已实现】`invariant`（实体不变式）：API 写入、`insert` / `save`、动作回写之前都会检查，违反则拒绝写入（R040）。
- 【已实现】`example f(1) == 2` 与 `test "名称" { … }` 内嵌在程序中，`aether test` 运行，Studio「测试」页展示。
- 【推测】静态证明契约（SMT），以及由契约自动生成测试（性质测试）。v0.2 只做运行时检查。

## 原则 5：效果与权限按"能力"授予
未来大量代码由智能体写，"它能做什么"必须显式、可审计。
- 【已实现】效果声明 `fn f() ! io, db`，检查器会顺着调用链计算函数实际产生的效果，未声明时给出 W300 警告与自动修复。
- 【已实现】基于角色的动作权限 `action reset() allow admin, auditor { … }`；HTTP 请求通过 `X-Aether-Role` 携带角色，不符返回 403；生成的界面带角色切换，受限按钮显示锁形字体图标（codicon lock）。
- 【部分实现】真正的"能力（capability）"应是不可伪造的令牌，并且可以向下传递、缩小权限。v0.2 的角色来自请求头，**没有身份认证**，只能作演示。

## 原则 6：人与智能体共享同一套语义
- 【已实现】诊断、契约、测试结果、历史都是结构化 JSON，人看界面，智能体读 JSON，看到的是同一份事实。
- 【已实现】可解释性：任何程序都能一键得到中文说明；每次修改都能回答"谁、何时、为什么、改了什么"。
- 【推测】智能体之间按同一协议协商、合并补丁；人只在价值与权限层面做决定。

## 原则 7：流程是一等公民
- 【已实现】`flow 名称 { step "a" { … } step "b" { … } }` 可执行：按顺序运行，步骤间通过 `ctx` 共享状态，任一步失败即停止，并记录每一步的结果与耗时。入口：`aether flow`、`POST /api/flow/名称`、标准库 `run_flow`、生成界面里的 播放字体图标（codicon play）按钮。
- 【推测】持久化、可恢复、跨天的长流程（重试、补偿、人工审批步骤）。

## 我们刻意不预测的事
- 具体语法会长什么样：语法只是投影，可以随时替换。
- 是否还需要"程序员"这个职业。可以确定的是，"定义正确是什么"这项工作不会消失。
