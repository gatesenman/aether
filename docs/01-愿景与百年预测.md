# Aether 愿景：100 年后的编程语言

## 1. 一个判断
今天的高级语言（Python、Java、TypeScript…）本质上是**给人读写的文本**：语法糖、缩进风格、隐式行为都为人类直觉优化。
当绝大多数代码由智能体（Agent）编写、由人类审阅时，语言的核心诉求会变成：

| 今天（为人设计） | 未来（为人 + 智能体设计） |
|---|---|
| 文本是唯一真相 | **结构化 IR（AST/JSON）是真相**，文本只是一种"视图" |
| 前端 / 后端 / 数据库分别用不同语言 | **一份意图描述**，编译到界面、API、存储 |
| 报错是给人看的字符串 | **结构化诊断**（错误码、位置、修复提示），机器可直接消费 |
| 修改 = 改文本 | **修改 = 结构化操作**（加字段、改名、替换声明），可验证、可回滚 |
| 副作用隐藏在函数里 | **效果（effect）显式声明**：io / db / net / time，智能体可安全推理 |
| 部署要配服务器、数据库、迁移 | 运行时自动建表、自动迁移、自动生成 API 与界面 |

## 2. 百年预测（分阶段）
- **2030 前后**：智能体写大部分样板代码；人类主要写"意图"和审阅 diff。语言开始提供机器可读诊断。（Aether 0.x 所处位置）
- **2050 前后**：前后端、数据库的边界在语言层面消失。程序员声明"实体、视图、动作、流程"，运行时决定在客户端、服务器还是边缘执行；存储与同步自动化。
- **2080 前后**：程序 = 可验证的意图图谱。每个修改附带证明（类型、效果、权限、性能约束），智能体之间以结构化补丁协作，人类做价值判断与授权。
- **2120**：编程语言更像"可执行的契约"——人用自然语言 + 少量精确声明表达目标，语言保证正确性边界；"前端/后端/数据库"只是历史名词。

## 3. Aether 的四个支柱
1. **统一应用模型**：`entity`（数据）+ `view`（界面）+ `action`（行为）+ `flow`（流程）。一份 `.ae` 文件 = 数据库表 + REST API + Web 界面。
2. **通用计算核心**：覆盖当代高级语言的主要能力——静态类型标注、泛型、一等函数与闭包、代数数据类型与模式匹配、模块、异常、异步并发、效果系统、管道运算符。
3. **为智能体而生的工具链**：JSON IR、结构化诊断、结构化补丁协议、可插拔大模型、无密钥 mock 模式。
4. **人机协作界面**：Aether Studio —— 人编辑、智能体提议、类型检查把关、人一键接受或拒绝，预览实时刷新。

> MVP 是这一愿景的"第一块砖"：它真实可运行，但规模与性能远未达到工业级，见 04-路线图.md。
